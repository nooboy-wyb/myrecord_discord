# Edge Discord 频道采集插件 v0.2.51

Discord 页面浮窗标题旁显示当前扩展版本。扩展后台每分钟请求已开启的频道标签页扫描页面；保底重载改为每个频道页固定间隔 30 分钟，每分钟最多重载一页，异常的前台页仍优先恢复。采集依赖 Discord 页面已加载出新消息；升级后须重新加载扩展并刷新各 Discord 标签页。

浮窗读取转发状态增加 12 秒超时和两次自动重试：本机服务卡住或未启动时，不会再显示 `A listener indicated an asynchronous response…` 这类消息通道错误，而是提示“本机转发服务 127.0.0.1:8765 没有响应”，并把按钮变成可点的“重新读取转发状态”。

自动加入的采集频道增加到九个：利润医生、交流频道、颜驰、熬鹰、风寻、颜驰 饭碗警报、颜驰 视频解说、柳玉东、匿名博士。重新加载扩展即会把缺少的频道写入允许频道，不必再在选项里手动填写。QQ 转发的去向按频道分开：利润医生只进群 1（主群），颜驰、风寻、颜驰 饭碗警报、颜驰 视频解说只进群 2（附加群），交流频道只进群 3（附加群）。

提前自恢复现在要求 Discord 标签页所在的 Edge 窗口也处于前台。仅在 Edge 窗口内被选中、但整个 Edge 已退到后台的页面，因浏览器计时器停顿而漏掉扫描心跳时，按正常定时巡检处理，不再误报异常自恢复。QQ 群消息发送增加每群至少 4 秒的间隔；明确返回 HTTP 400 / `40034100` 的限频拒绝记录为 `rate_limited`，冷却两分钟后自动重试，不把它当作发送结果不明而永久暂停群转发。

异常与刷新事件现在写入本机 `data/collector-diagnostics.sqlite`，包括触发原因码、频道、标签页、事件开始时间、重载请求与加载时间、扫描恢复、重试次数和错误文本。本机服务暂不可达时扩展先保存在 `diagnosticQueue`，每分钟补写；弹窗显示待写入条数。用 `node scripts/show_collector_diagnostics.cjs --channel <频道ID> --limit 100` 按频道查看，或加 `--incident <事件开始的毫秒时间戳>` 串联一次异常。旧版没有保存的事件无法追补。

QQ 转发若在读取本机原图时就失败，记录为 `failed_preflight`，原图稍后保存成功后可自动重试；只有已经开始调用 QQ 接口却没有明确结果的分段才保持 `unknown` 并暂停该群，以防重复发送。旧的“原图未保存”记录在服务启动时安全重分类，并写入 `QQ_IMAGE_PREFLIGHT_RECLASSIFIED` 诊断事件。

正常轮流重载对每个已打开的频道页按固定 30 分钟间隔安排；每分钟巡检最多选择一页，因此多个页面同时到期时会依次完成。活跃页停扫约两分钟仍立即尝试自恢复，失败后固定每 2 分钟重试。被 Edge 休眠的非活动页到正常轮流时间重载，不再误报“异常自恢复成功”。

连续发言的作者继承改为沿页面消息正文节点的顺序回查最近十分钟内可见的作者标题，不再要求前一个节点必须是 `li` 同级；采集载荷记录作者是直接读到、从前一消息继承，还是未知。已入库记录的作者为空时，后续扫描读到作者会补齐 `author_display` 并写入 `discord_web_author_updates` 审计表；初次采集的 `payload_json` 不改。

临时巡检测试改成单轮：保持扩展弹窗打开，每 10 秒重载一个已允许且打开的 Discord 频道页；每页完成加载后通过 QQ 警报机器人私聊一条明确标注“巡检测试”的结果。每个页面只测试一次，全部完成后自动退出，恢复正式的固定 30 分钟轮流刷新。正式的健康页面刷新不发 QQ 通知；只有异常自恢复的结果仍按原规则通知。

后台标签页可能被 Edge 限制内容脚本定时器。现在只有前台 Edge 窗口内的活动频道页在两分钟停扫时立即进入自恢复；非活动页按固定 30 分钟间隔轮流巡检重载，被浏览器丢弃的非活动页也按此间隔处理。这样避免后台页因没有扫描心跳而每几分钟重复重载并发“恢复成功”。代价是非活动页的真实停采可能到轮流巡检时才被发现；需要更快发现时应保持该频道为活动页或另建独立采集方式。

巡检不再等待扩展待入库队列完成上传，以免大量积压或网络超时拖住每分钟的页面健康检查。升级后请在 `edge://extensions` 重新加载扩展，并刷新各 Discord 频道标签页；仅修改项目文件不会替换 Edge 正在运行的旧服务工作线程。

本机服务对同一频道同类恢复私聊增加 40 分钟限流，避免旧版扩展在升级前反复报告“恢复成功”；未恢复告警仍单独计数。

连续恢复失败时固定每 2 分钟重试；首次发现活跃页停扫仍立即重载，私聊人工检查告警仍在两分钟未恢复时发送一次。

后台巡检使用每分钟的扩展闹钟，弹窗关闭后仍会唤醒服务工作线程。现在只在闹钟缺失时创建，避免线程反复启动时把下一次巡检推迟；巡检也不再等待待入库队列上传完成。弹窗显示巡检心跳，超过三分钟未更新会提示异常。巡检需要 Edge、扩展和频道标签页仍在运行。

“扫描当前页面”现在会重新提交当前可见的全部消息，即使扩展此前已经见过相同正文；本机按消息 ID 与内容去重。这用于恢复扩展队列曾丢失、但页面仍可见的消息。页面自动扫描仍只提交新观察或内容变化。

批量扫描时待入库消息的入队与出队现串行写入扩展本地队列，避免同时读写覆盖导致个别已识别消息丢失。超过 2000 条时弹窗显示告警；实际历史漏发仍需核对本地 SQLite 和 QQ 发送记录。

巡检发现某频道采集异常后会直接尝试自恢复，不发送“开始恢复”私聊。同一次异常的每次重载若在两分钟后仍未识别到消息，就记录一次失败并继续重试；连续两次失败后才发送一次需要人工检查的 QQ 告警。若在达到告警门槛前恢复，只记持久化诊断和服务日志，不发送 QQ 成功通知；告警后最终恢复时发送一次“恢复成功”。恢复状态先落盘，再提交诊断和告警；已恢复事件的待发送超时告警会取消，服务端也会按持久化诊断记录拦截过期超时和重复成功告警。每次自恢复的开始、失败、重试与恢复时间写入 `data/collector-diagnostics.sqlite`，并在 `data/logs/collector-YYYY-MM-DD.log` 留下摘要。手动刷新、10 秒测试刷新和健康页面的定时巡检不启动新的告警事件。通知提交失败会留在扩展本地队列，后台按分钟重试。更新后须重新加载扩展、刷新 Discord 页面，并重启 `start_discord_qq.ps1` 常驻服务。

弹窗可开启临时“10 秒刷新测试”。保持弹窗打开时，扩展约每 10 秒轮流重载一个允许采集的 Discord 标签页；弹窗保存最近 8 次实际刷新的频道、请求、加载完成和恢复扫描时间，并显示下次预计刷新时间。点击关闭测试模式后恢复正常的固定 30 分钟轮流巡检；若直接关掉弹窗，每分钟的后台巡检会检测测试心跳过期并自动退出测试模式。测试会频繁重载页面，仅用于短时验证。

Discord 页面右侧浮窗现按三个入口排列：当前频道实时转发启停、历史漏发查看与补发、按北京时间检查入库与扫描当前页面。取消手动补发位于历史补发清单内；按时间检查只查询本机已归档消息，扫描只处理页面当前已加载的消息。

## 安装

1. 安装 Node.js 22.5 或更新版。在项目根目录运行 `powershell -ExecutionPolicy Bypass -File scripts/start_discord_collector.ps1`，保持终端窗口打开。启动脚本会读取当前 Windows 代理设置，供图片下载使用。
2. 打开 `edge://extensions`，开启左下角“开发人员模式”，点“加载解压缩的扩展”，选择本目录 `edge-discord-collector`。
3. 打开插件“扩展选项”，逐行输入需要采集的 Discord 频道 URL；可用“名称 | URL”指定 QQ 展示名称，例如“颜驰 | https://discord.com/channels/1222459489333018634/1254782508793593947”。交流频道、颜驰、利润医生、熬鹰、风寻、颜驰 饭碗警报、颜驰 视频解说、柳玉东、匿名博士这九个频道会由扩展自动加入采集列表。从 `data/collector-token.txt` 复制令牌到设置中，保存。
4. 在 Edge 登录 Discord 并打开指定频道，刷新页面。点击扩展图标查看扫描时间、待发送数量和最近入库时间。
5. 数据保存在项目的 `data/YYYY-MM-DD/messages.sqlite`。可用 SQLite 查询 `discord_web_messages` 表，正文在 `body_raw`，原图链接在 `attachments_json`。下载状态见 `discord_web_attachment_files`，原图文件在同日 `attachments/`。

Edge 会显示该扩展可读取 `discord.com` 页面数据的权限提示；这是 DOM 采集所需权限。扩展还可连接本机 `127.0.0.1:8765`，不会把数据发到其他地址。

页面变化会触发采集，内容脚本每 15 秒补扫一次。扩展后台每分钟请求各监控页扫描并检查心跳；前台 Edge 窗口内的活跃页停扫超过 2 分钟时优先重载，非活动页按固定 30 分钟间隔轮流重载，每轮最多一页，避免多个 Discord 页同时抢占资源。弹窗的“刷新一个采集页”每次也只重载一个页面，可重复点击以轮流刷新。刷新前会先重试待入库队列；弹窗分别显示本轮刷新请求数和真正完成页面加载的标签页数。更新扩展文件后须在 `edge://extensions` 点击重新加载并刷新 Discord 标签页。若 Edge 将 Discord 标签页置于休眠状态，可在“系统和性能 → 性能 → 始终保持这些站点处于活动状态”添加 `https://discord.com`，但保持 7～8 个 Discord 标签页常驻仍会占用较多内存。

自动恢复会逐页记录扫描心跳、页面重载完成时间、重载后是否重新识别出消息。仅收到页面加载完成事件不算恢复；重载后扫描到消息才将该页标为正常。连续未恢复时固定等待 2 分钟再次尝试；仍然一次只重载一页。扩展图标徽标及弹窗显示正在恢复、未恢复和重试次数。此机制只能在 Edge 和扩展运行、目标频道标签页仍打开时工作；页面能扫描不能证明 Discord 的实时连接正常，QQ 发送状态仍须另行核对。

扩展区分两项验证：重新扫描到旧消息只证明页面与解析器恢复；只有同一频道出现比此前记录更新、且创建时间不早于恢复观察窗口的 Discord 消息，才显示“已见新消息”。向下滚动到较新的历史消息不会被误判成实时恢复。安静的频道可能长时间等待新消息，但不会因此无限重载。待恢复频道按最后成功扫描时间从久到近排序，优先处理停扫最久的一页。

自动检查在当前 Windows 登录期间、Edge 与对应 Discord 频道标签页保持打开时持续运行；本机采集与 QQ 服务也须保持运行。当前没有配置开机自启，也不会因用户主动关闭 Edge 或频道标签页而重新打开它们。

即使某页持续扫描到旧消息，扩展也会按固定 30 分钟间隔轮流重载它，以降低 Discord 实时连接静默停滞的风险；始终一次只重载一个页面，停扫的异常页优先。巡检重载后仍分别核对“页面可读”与“出现新消息”。

Discord 页面右侧“本地采集状态”浮窗提供“历史未转发补发”入口。它只针对当前频道，按已配置路由显示目标 QQ 群；每次列出最近最多 20 条在该群没有发送尝试的本地归档消息。原图不完整的消息会显示但不能勾选。点击发送后显示请求状态；已有发送尝试或正在排队的消息不会重复提交。需要重启本地服务并重新加载扩展后使用。

浮窗外层另有“取消历史补发”按钮，仅取消当前频道的手动补发请求。待发送的消息会立即取消；正在发出的一条消息可能完成，后续消息停止。已被 QQ 接受的消息无法撤回。自动转发不受此按钮影响。

采集器也识别 Discord 媒体代理的 `/external/` 图片。柳玉东消息如果正文提到“图二”等，但本地没有图片附件，手动补发清单会标为暂不能发送；需要在 Discord 页重新加载并让图片实际显示，才能重新采集。

扫描图片时会检查同一条消息的外层列表节点。v0.2.49 同时识别 Discord 使用 `chat-messages-<频道 ID>-<消息 ID>` 格式标识的纯图片消息；文字和紧随其后的图片若是两条独立消息，会分别归档和转发，不会误归到同一条。

v0.2.21 会规范化附件 URL 末尾多余的 `&`，避免同一张 Discord 原图因链接写法不同被重复记录。柳玉东实时消息由本机转发器等待 90 秒且两张原图均已保存后再发送；未满足条件时继续等待，不提前发送纯文字版本。

## 范围

只采集当前 Discord 页面实际加载的消息。页面未打开、进入休眠、断网或 Discord 改版时可能漏采；弹窗中的扫描时间可用于发现停采。扩展选项可逐行配置多个频道 URL，但每个频道页面需要在 Edge 中保持打开。作者和时间取决于 Discord 当前 DOM 是否在该消息节点中提供。只下载消息的原始附件图片，不采表情包、贴纸、头像或徽章。图片 OCR 和信号标签尚未接入。QQ 转发有独立的本机启动脚本，尚未完成持续运行实测。完整设计和已知限制见 [架构文档](../docs/discord-ocr-architecture.md)。
