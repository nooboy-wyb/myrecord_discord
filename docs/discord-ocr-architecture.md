# Discord 频道采集与归档架构

更新：2026-10-30。本文以正在运行的 Edge 插件和本机服务为主；原先的截图 OCR 流程保留为历史证据和可选补充。

## 目标与边界

用户在 Edge 中登录 Discord，打开并保持指定频道页面。扩展只读取允许列表中的频道、且只读取网页当前已渲染的消息；无需 Discord bot 权限。正文直接取网页 DOM，图片只采集消息附件的原始文件，不采表情包、贴纸、头像或徽章。SQLite 保存消息及观察记录，磁盘保存原图。当前没有 QQ 转发、信号判定或图片 OCR。

页面未打开、被休眠、断网、登录失效或 Discord DOM 改版时可能漏采。虚拟滚动意味着只能保证观察到的消息，不能宣称覆盖整个历史频道。

## 当前数据流

```text
Edge 中的 Discord 指定频道
  → Manifest V3 内容脚本：DOM 消息、作者、时间、完整正文、原图地址
  → 扩展本地待发送队列
  → http://127.0.0.1:8765/v1/messages（随机令牌）
  → data/YYYY-MM-DD/messages.sqlite
  → data/YYYY-MM-DD/attachments/（下载的原图）
  → messages-readable.md（只读导出）
```

内容脚本监听页面变化，变化持续发生时最多约每 100 毫秒触发一次扫描，另每 5 秒扫描一次。这样快速滚动历史时不会因为连续页面变化而一直推迟扫描；网页未加载到的消息仍无法采集。消息发送失败留在扩展队列，后台定时重试。2026-10-30 的 36 条不同消息样本中，Discord 时间至首次入库的中位数为 5 秒，约 90% 在 12 秒内；刷新后补采的旧消息可晚数分钟。这是实测值，不是延迟保证。

扩展根据频道 URL 提取服务器 ID 和频道 ID；消息 ID 与正文来自 DOM。网页不重复显示连续消息的作者时，内容脚本尝试沿用前一条消息作者。可读导出也对数据库中作者为空的旧记录按消息 ID 顺序沿用上一条作者，并明确标注。这是派生展示，不覆盖原始 `author_display`；跨消息组、缺页或页面结构变化时仍需人工核对。

附件只接受 Discord CDN 的 `/attachments/` 图片地址。优先取消息的原图链接；预览图地址会转成 `cdn.discordapp.com` 的原图地址，并移除宽高、格式与质量等预览参数，保留签名参数。下载失败保留原链接和错误；正文入库不依赖图片下载成功。Windows 使用本地代理时，启动脚本读取系统代理并让 Node 下载走该代理。

## 存储与去重

按北京时间采集日期分库：`data/YYYY-MM-DD/messages.sqlite`。网页采集的主要表为 `discord_web_messages`、`discord_web_observations`、`discord_web_attachment_files`。前者保留 DOM 原文、附件链接、Discord 时间和采集时间；观察表记录重复观察；附件表记录原图下载状态、路径和 SHA-256。原图以内容 SHA-256 命名，相同文件只存一份。当前唯一键为同日的频道 ID、消息 ID、正文与附件内容哈希；同一消息正文或附件变化会留下新记录。

当前尚无跨日全局去重索引，也没有可靠的编辑版本、漏采报警或后台冻结恢复机制。`channel_name` 和 `author_display` 都依赖 Discord DOM，可能混入角色文字或取错；关联与去重以频道 ID、消息 ID 为准。导出时可合并同一消息的重复观察，但不能把合并结果当成原始记录。

## 原截图 OCR 流程

`scripts/ingest_discord_samples.py` 与 `src/discord_archive/store.py` 处理 `scence_print` 中的旧截图。它们将原始截图、OCR 行、坐标和置信度存入同一日期数据库的 `captures`、`ocr_lines`、`messages` 等独立表。截图分组消息与网页直接采集的消息来源不同，不应混淆。旧 OCR 全文可用 `scripts/export_discord_archive.py` 导出为 `archive.txt`；其中包含侧栏等非消息文字。

网页正文不需要 OCR。若以后需要读取图表或其他原图中的文字，再对已保存原图单独做 OCR，并把 OCR 原文、模型、时间及人工修正另存；不得改写 `body_raw`。

## QQ 发送端决策（待实测，未接通）

本项目需要在 Discord 出现消息后**主动**向用户的 QQ 私聊或自有群发消息。2026-10-30 重新核对的 [QQ 机器人官方文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html) 明确列出群聊主动消息、频控与[群消息发送接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。此前依据旧版文档认定官方机器人不能主动推送的结论已过时。首选验证 QQ 官方机器人；仍须实际测试目标群的权限、消息长度、正文及原图送达情况。

官方路径需要用户在 QQ 开放平台注册并创建独立机器人，将机器人加入目标群。它不等于通过当前登录的个人 QQ 账号发消息。发送接口使用群 `group_openid`，不能直接把数字群号当作 `group_openid`。个人或未认证主体的服务范围、机器人进群资格需按平台实际设置确认。群消息支持文本与富媒体；原图需先上传取得 `file_info` 再发送。若官方路径无法满足实际需求，再单独评估 NapCat 等第三方方案，不默认安装或接管当前 QQ 客户端。

已添加群 OpenID 监听工具：运行 `scripts/get_qq_group_openid.ps1`，在终端本地输入当前入群机器人的 AppID 与重置后的 AppSecret；看到“机器人已登录 QQ Gateway”后可检查管理后台在线状态，在目标群 `@机器人 测试` 一次可获取群标识。工具只保存该事件的 `group_openid` 到 `data/qq-group-openid.json`，不保存群消息正文。窗口保持打开时维持 Gateway 心跳，关闭后机器人可能重新显示离线；它尚未实现消息回复或 Discord 自动转发。
