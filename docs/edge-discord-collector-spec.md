# Edge 插件采集 Discord 频道消息：独立开发说明

> 这是开发前的历史规划，部分内容（尤其图片 OCR、表结构和 QQ 转发）尚未实现。当前实际架构与运行状态以 [Discord 频道采集与归档架构](discord-ocr-architecture.md) 为准。

## 目标

在用户已登录的 Microsoft Edge 中，监控用户指定的 Discord 网页频道。插件逐条读取当前网页实际加载的消息，保留频道、用户名、显示时间、完整正文与图片；本地服务按北京时间每天存入 SQLite。图片中的文字用本地 OCR 另行识别。后续可给消息添加“信号”标签，并转发到 QQ。无需 Discord bot 权限。

本说明是待开发方案。现有 V0 只有静态截图 OCR 与样本 SQLite 归档；没有浏览器插件、自动截图或 QQ 转发。

## 采集原则

1. Edge Manifest V3 扩展仅匹配 `https://discord.com/*`。用户在扩展设置中填写允许采集的频道 URL/频道 ID，默认不采集其他频道。
2. 内容脚本读取网页 DOM 中已渲染的消息容器，提取频道 ID、消息 ID（若 DOM 中可取得）、作者显示名、Discord 显示时间、完整正文、附件图片 URL、消息链接。监听 DOM 新增和更新，并在启动时扫描当前可见消息。
3. 不以 OCR 识别网页正文；OCR 只处理图片内容及必要时的截图证据。网页正文与图片 OCR 结果必须分字段保存，不能混合或覆盖。
4. Discord 可能只渲染当前可见的一部分历史消息。插件只承诺采集它实际观察到的消息；不要声称已抓取整个频道历史。页面结构改变或后台冻结时要报告故障。
5. 插件普通 `captureVisibleTab` 只能截窗口中当前激活的标签页。后台采集以 DOM 消息为主；截图是可选证据，不能作为后台监控的唯一来源。

## 单条消息数据格式

```json
{
  "schema_version": 1,
  "source": "discord_web",
  "guild_id": "可取得则填写，否则 null",
  "channel_id": "频道 ID",
  "channel_name": "交流频道",
  "source_message_id": "可取得则填写，否则 null",
  "message_url": "可取得则填写，否则 null",
  "author_display": "豆沙包APP",
  "displayed_time": "17:16",
  "source_timestamp": null,
  "captured_at": "2026-10-30T19:36:25+08:00",
  "body_raw": "完整正文，保留原有换行，不省略",
  "attachments": [
    {
      "kind": "image",
      "source_url": "Discord 图片 URL",
      "local_path": "data/2026-10-30/attachments/文件名.png",
      "sha256": "下载后的文件校验值",
      "image_ocr_raw": "图片 OCR 原文；尚未处理时为 null"
    }
  ],
  "derived_labels": [],
  "capture_method": "dom",
  "review_status": "unreviewed"
}
```

`body_raw`、图片原件和首次采集记录不可被 AI 分析或人工修正覆盖。`source_timestamp` 只在网页可取得可靠完整时间时填写；不要把 `17:16` 猜成完整日期。OCR 原文、修正、信号判断和转发记录应各自追加版本。

## 本地服务和存储

- 插件将消息发送到本机回环地址的采集服务，例如 `http://127.0.0.1:8765/v1/messages`。服务只监听 `127.0.0.1`，使用本地随机令牌校验；不要暴露到公网。
- 服务先将消息写入 SQLite，再返回成功。失败时插件保留待发送队列并重试，不能仅凭浏览器控制台日志视为已保存。
- 按**北京时间采集日期**保存：`data/YYYY-MM-DD/messages.sqlite`、`screenshots/`、`attachments/`。原图文件放磁盘，数据库存路径、哈希及元数据。
- 优先用 Discord 消息 ID 去重；取不到时用频道 ID、作者、时间、正文和附件哈希构造暂定指纹。重复观察保留采集记录，避免重复转发；编辑后的消息须保留新版本，而不是静默覆盖旧文。
- 数据表至少包含 `messages`、`message_versions`、`attachments`、`image_ocr`、`capture_observations`、`derived_labels`、`forward_attempts`。对跨天同一消息的去重需有跨日索引或轻量总目录。

## OCR、信号和 QQ 输出

处理顺序：**DOM 原文入库 → 图片原件下载入库 → 图片 OCR → 信号判定 → QQ 转发**。OCR 失败不应阻止正文和图片保存。图片 URL 可能失效，应尽快下载原件；下载失败记录状态和原 URL。

QQ 文本格式：

```text
【Discord｜交流频道】豆沙包APP · 17:16
【信号】（仅在判定为信号时显示）
完整消息正文，保持原有换行，不截断、不改写
```

图片作为 QQ 图片附件一并发送。图片 OCR 原文默认只存库；若需要转发，放在正文之后并明确标为“图片文字识别”，不得冒充作者输入的正文。`【信号】`是独立的派生标签，须保留判定规则或模型版本、时间和置信依据。转发成功与失败均写入 `forward_attempts`；失败可重试，不能重复发送已确认成功的版本。

## 验收标准

1. 用户安装解压缩的 Edge 插件，指定一个频道并保持该网页打开；无需 bot 权限。
2. 连续出现至少 20 条测试消息时，每条的频道、用户名、时间、**完整正文**及图片均可在数据库查询；换行和图片顺序可核对。
3. 网页在其他窗口后方持续运行时，记录新消息的捕获延迟与漏采情况；页面冻结、断网、登录失效和 DOM 规则失配均显示明确状态，不把旧页面当新数据。
4. 重启插件与本地服务、重复扫描页面，不产生重复消息或重复 QQ 转发；编辑消息保留旧版与新版。
5. OCR 错读（例如 `76,0990.00`）原样保存，信号判断不能修改原始正文；转发正文不得出现省略号代替内容。

## 分阶段交付

- **V1a**：Edge 插件读取指定频道 DOM，发送完整消息及图片元数据到本地服务，SQLite 入库；提供查看采集状态和错误的界面。
- **V1b**：下载原图片、运行本地图片 OCR，保存截图证据与 OCR 版本；做后台运行和漏采测试。
- **V1c**：派生信号标签并接 QQ 转发，记录每次转发结果。

开发时需以真实 Discord 页面验证选择器，不能只用静态 HTML 样例。网页改版时，应能更新解析规则并保留历史数据。
